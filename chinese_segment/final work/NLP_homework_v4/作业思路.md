# 文献综述 Agent —— 课程大作业方案（一周版）

> 中文信息处理课程期末项目 | 建议 1 周完成

## 一、项目定位

做一个**简化版文献综述助手**：用户输入一个研究主题，系统自动检索相关文献、抽取关键信息、做主题归纳，并生成一份结构化综述草稿，配一个简单的前端页面展示。

考虑到只有一周时间，**砍掉**引用关系图谱、完整 agent 任务规划、知网爬虫等高风险模块，集中精力把"检索 → 中文信息抽取 → 综述生成 → 可视化"这条主线跑通。其中**中文信息抽取**是和课程最贴合、最容易拿分的部分，应作为重点。

## 二、功能模块（按优先级）

### 模块 1：文献检索（必做，难度低）

- 接入公开 API，优先 **arXiv** 和 **Semantic Scholar**（免费、文档清晰、无需爬虫）
- 支持关键词检索、时间范围筛选
- 多来源结果按标题去重

> 提示：arXiv API 返回 XML，Semantic Scholar 返回 JSON，都很好解析。中文文献接口受限，建议本期不碰知网，避免爬虫合规和反爬问题拖慢进度。

### 模块 2：中文信息抽取（必做，重点，课程核心）

这是评分关键，建议多投入：

- 从摘要 / PDF 文本中结构化抽取：标题、作者、年份、关键词、研究方法、核心结论
- **中文命名实体识别（NER）**：抽取技术名词、数据集名称、评测指标等
- 实现方式二选一或结合：
  - 传统方法：jieba 分词 + 规则/词典匹配（体现"中文信息处理"基本功）
  - LLM 方法：调用大模型做结构化抽取，输出 JSON
- 建议两种都做一点，在报告里做对比，是很好的加分点

### 模块 3：主题整理与聚类（选做，难度中）

- 用文本 embedding（如 sentence-transformers 中文模型）+ KMeans 做主题聚类
- 自动归纳出几个研究方向，每个方向列出代表文献
- 时间趋势统计（按年份的论文数量）

### 模块 4：综述自动生成（必做，难度中）

- 把抽取后的结构化文献喂给 LLM，生成结构化综述：
  研究背景 → 主要方法分类 → 各类对比 → 研究空白 → 未来方向
- **关键要求**：生成时标注引用来源（如 [1][2]），降低幻觉，便于核查

### 模块 5：前端可视化（必做，难度看团队）

- 文献列表：可筛选、排序、打标签
- 关键词词云
- 发表年份趋势折线图
- 主题聚类的分组展示
- 综述草稿展示区
- 技术选型：时间紧可用 **Streamlit / Gradio** 快速搭（Python 一把梭，最省时）；前端基础好可用 React + ECharts

## 三、技术栈建议（一周友好）

| 部分 | 推荐方案 | 理由 |
|------|---------|------|
| 后端 / 逻辑 | Python | 生态全，NLP 库多 |
| 检索 | arXiv API、Semantic Scholar API | 免费、无需爬虫 |
| 中文 NLP | jieba、sentence-transformers、HanLP（可选） | 课程相关，体现基本功 |
| 抽取 / 综述 | LLM API（如可用） | 结构化抽取与生成 |
| 聚类 | scikit-learn (KMeans) | 简单成熟 |
| 前端 | Streamlit / Gradio（首选）或 React + ECharts | 省时优先 |
| 数据存储 | SQLite 或本地 JSON | 轻量够用 |

## 五、能体现 "Agent" 的轻量做法（选做加分）

不用做完整任务规划，做一个**简单的流程编排**即可称为 agent 雏形：

- 用户输入一句话主题 → 系统自动串起"检索 → 抽取 → 聚类 → 综述"流水线
- 每步输出对下一步可见，最后汇总
- 报告里说明这是基于固定流程（pipeline）的 agent，并讨论如何进一步扩展为可自主决策的版本（如让 LLM 决定是否扩大检索）

## 六、评分加分点提醒

- 中文信息抽取部分做出**传统方法 vs LLM 方法**的对比实验
- 综述生成做到**可追溯引用**，并讨论幻觉问题
- 报告里包含抽取准确率等**量化评估**（哪怕小规模人工标注几十条）
- 演示流畅，前端清晰

## 七、可能的坑

- 知网/中文库爬虫：合规与反爬风险高，本期不建议
- PDF 解析：扫描版 PDF 抽取困难，优先用摘要文本，PDF 解析作为可选
- LLM 幻觉：综述里出现不存在的文献，务必做引用核查
- 时间分配：不要在前端炫技上花太多时间，核心是 NLP 抽取

## 八、项目进阶实录（超额完成记录）

在实际的开发迭代中，我们不仅完成了上述所有的核心与进阶要求，还额外实现了大量高阶功能，使项目达到了远超“课程大作业”的完整度：

1. **并行数据抓取与 Github 防封**：我们不仅接入了 arXiv 和 Semantic Scholar，还通过并发请求拦截 Hugging Face Papers 的 GitHub 仓库和 Star 数据。特别设计了基于 HTML 网页的正则兜底刮取机制，完美突破了 GitHub API 极其苛刻的 Rate Limit。
2. **PyPDF2 全局全文解析与按需精读**：引入了 `PyPDF2` 和强大的 HTML 净化正则，不局限于摘要，而是支持抓取全文的前 4 万字符。我们在前端设计了“✨精读分析”机制，能通过大模型挖掘出诸如“数据集规模、评测指标细节、硬件算力瓶颈”等隐藏极深的专业学术细节。
3. **算法演进路线图提取**：我们在综述生成中要求大语言模型自动生成 Mermaid 代码描述技术演进。针对大模型偶尔忘加代码块标记的问题，我们开发了容错率极高的双层后处理嗅探引擎，保证图表渲染万无一失。
4. **一键学术海报生成引擎**：在前端加入了一键学术海报排版与生成功能，智能组合综述摘要、原论文关键插图以及自动绘制的算法演进图，可直接用于学术汇报打印。
