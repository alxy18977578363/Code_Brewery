# 文献综述 Agent · 项目总览

> 中文信息处理课程大作业。本文档面向团队内部，用于**快速熟悉整个项目**：我们做了什么、
> 系统怎么跑、每个代码文件负责什么。需要更细的设计动机可看 `docs/DESIGN.md`，
> 使用说明可看 `README.md`。

---

## 一、这是什么

一个**文献综述智能体（Agent）工具**。用户在网页输入一个研究主题（如「检索增强生成」），
系统自动跑完一整条流水线，最后产出一份**带可追溯引用的中文综述** + 一系列可视化分析 + 学术海报。

它解决的痛点：科研调研时要手工检索、逐篇读英文论文、归纳「谁用了什么方法、在什么数据集上、
取得什么效果」，非常耗时；而直接让大模型写综述又会**编造论文和引用（幻觉）**。
本项目用 **RAG（先检索真实论文，再让大模型基于真实资料写作）** + **多智能体协作 + 幻觉检测**
来同时解决「效率」和「可信」两个问题。

**核心流水线（六个阶段）：**

```
用户输入主题
   │
   ▼
① 查询翻译   中文主题 → 英文检索词（arXiv 基本全英文）
   ▼
② 双源检索   arXiv + Semantic Scholar → 跨源去重 → IDF 相关性重排 → 抓 GitHub 代码/Star
   ▼
③ 中文信息抽取  规则法 / 大模型法，抽出 方法·数据集·指标·结论（评分核心）
   ▼
④ 主题聚类 + 趋势分析   TF-IDF + KMeans 分组；方法演变、数据集/指标频次、近两年热点
   ▼
⑤ 多智能体综述写作   Planner→Writer(并发)→Grounding→(可选 Auditor→Reviser 返工)
   ▼
⑥ 可视化展示   词云 / 趋势图 / 聚类卡 / 演进图 / 学术海报 / 论文问答
```

## 二、我们完成了哪些任务

### 1. 作业硬性要求（全部完成）

| 作业要求 | 完成情况 |
|---|---|
| 自动爬取主题相关论文（arXiv）及其 GitHub 代码，优先有公开代码的 | ✅ `arxiv_client` + `enricher`，按 Star 排序 |
| 生成介绍调研文献的文档（含方法、数据集、结果，自动形成引用标注） | ✅ 多智能体综述 `generator`，每句强制 `[n]` 引用 |
| 自动绘制算法发展演进图 + 学术海报 | ✅ Mermaid 演进图 + 一键海报（`static/app.js`） |
| 论文主题准确率 ≥ 85% | ✅ IDF 相关性重排 + `eval/topic_eval.py` 评测 |
| 综述文字无明显幻觉 | ✅ 引用越界检测 + 张冠李戴（Grounding）检测 |
| 算法演进图无明显时间错误 | ✅ `_validate_and_fix_mermaid` 时间校验自动纠正 |

### 2. 额外完成的创新/工程功能

- **两条抽取路线并存**：规则法（jieba+词典+正则）与大模型法输出字段完全一致，可量化对比。
- **抽取质量量化评测**：`eval/compare.py`（CLI）+ 前端「抽取方法评测」面板，给出数据集/指标的 P/R/F1。
- **多智能体协作写作**：Planner（规划）→ Writer（并发分章节写）→ Grounding（查幻觉）。
- **多智能体审查返工**：Auditor（找茬）+ Reviser（重写），三档强度（Level 1/2/3）。
- **AI 选题助手**：检索**前**对话式帮用户把模糊想法收敛成检索词。
- **论文问答（RAG QA）**：检索**后**基于当前文献列表答疑，答案带 `[n]` 引用并校验越界。
- **趋势与统计分析**：方法随年份演变、数据集/指标频次排行、近两年热点方法。
- **高并发引擎**：多 API Key 轮询 + 线程池随密钥数动态扩容（`min(20, 5×密钥数)`）。
- **优雅降级**：没有大模型密钥也能跑——翻译、抽取、综述、问答全部退回规则/模板版。

## 三、核心数据结构

整条流水线就靠两个数据类（定义在 `src/models.py`）串起来：

- **`Paper`**（检索阶段产物）：`paper_id` / 标题 / 摘要 / 作者 / 年份 / 来源 / 原文链接 /
  代码链接 / GitHub Star 数 / 全文（精读时填）。
- **`StructuredRecord`**（抽取阶段产物）：`paper_id` / 标题 / 年份 / 关键词 / **方法 methods** /
  **数据集 datasets** / **指标 metrics** / 定量结果 results / 精读详评 detailed_analysis / 结论 /
  抽取来源 extracted_by。

> 关键约定：**规则法和大模型法输出的 `StructuredRecord` 字段完全相同**，这正是能做对比、能统一渲染的前提。
> 改字段时要同时改：两个抽取器 + `eval/labeled.json` + 评测脚本 + 前端表格。

### 文件作用详解（按模块）

#### 入口与配置

- **`app.py`** — Flask 入口。注册所有 HTTP 端点（见第五节），把前端请求转发给 `pipeline` /
  各 `review` 模块；并在 `__main__` 里关掉 Werkzeug 自动重载（避免 Windows 下 `WinError 10038`）。
- **`config.py`** — 用 `python-dotenv` 读 `.env`。把 `DEEPSEEK_API_KEY` 按逗号拆成 **密钥列表**
  `DEEPSEEK_API_KEYS`（多 Key 轮询的基础）；`llm_available()` 是所有 LLM 路径的总开关。

#### 检索模块 `src/retrieval/`

- **`arxiv_client.py`** — 调 arXiv 公开 API，返回 Atom XML 用 `feedparser` 解析成 `Paper`。
  年份过滤在客户端做（API 不支持）；**默认绕过本机代理**（国内代理常拦截公网学术接口）。
- **`semantic_scholar_client.py`** — 调 S2 Graph API（JSON）。带「被引用次数」做质量排序，但对
  **近两年新论文豁免引用门槛**（否则前沿工作会因引用没攒够被排除）；遇到限流 429 静默返回空。
- **`translator.py`** — 主题含中文时翻译成英文检索词。优先用 DeepSeek（提示词**强制保留每个限定词**，
  避免「中文命名实体识别」被压成「named entity recognition」丢掉「中文」）；LLM 不可用时退回内置术语表。
- **`dedup.py`** — 把两个数据源的结果按「标题归一化（小写、去非字母数字）」去重。
- **`enricher.py`** — 流水线的「增强」环节，用线程池并发：从 HuggingFace Papers / PapersWithCode
  抓 GitHub 仓库链接和 Star 数（GitHub 403 限流时改用浏览器 UA 直接爬网页）、抓 arXiv 配图、
  抓全文（arXiv HTML，失败用 PyPDF2 解析 PDF）。

#### 抽取模块 `src/extraction/`（评分核心）

- **`base.py`** — `BaseExtractor` 抽象基类，规定 `extract(paper) -> StructuredRecord` 接口，
  让规则法和大模型法可以无缝替换。
- **`rule_based.py`** — 规则法。启动时把三套词典里的中文术语 `jieba.add_word` 进分词器（避免
  「自注意力」被切碎）；用词典匹配方法/数据集/指标，用正则补抽「数字+%+F1/accuracy」的指标数值，
  用 `jieba.analyse` 抽关键词，用触发词（「实验表明」「we propose」等）定位结论句。**本地秒级、可解释。**
- **`llm_based.py`** — 大模型法。把标题+摘要(+全文)交给 DeepSeek，强制返回固定字段的 JSON；
  方法/数据集/指标归一化为英文便于聚合，结论/详评用中文；抽取失败返回「字段空但保留 paper_id」的记录，
  保证流水线不中断。
- **`evaluator.py`** — **抽取评测核心（无副作用，CLI 与 Web 共用同一把尺子）**。在 `eval/labeled.json`
  上对每个抽取器算**数据集/指标的 P/R/F1** 和结论关键词命中率。`run_comparison()` 供前端调用。
  （注：方法名表述太宽泛、难规范化，已从对比中移除，只比数据集和指标。）

#### 聚类与分析 `src/clustering/topic_cluster.py`

- `cluster_papers()`：TF-IDF + KMeans，按论文数自动选簇数（<4 不聚类，最多 5 类），用簇中心高权重词
  + 高频方法词当主题标签。
- `year_trend()`：各年份论文数（折线图数据）。
- `trend_analysis()`：**新增的学术分析**——主流方法逐年演变（多折线）、数据集/指标频次排行、近两年热点方法。

#### 综述与多智能体 `src/review/`

- **`generator.py`** — 综述生成主流程，本项目工程深度最高的文件：
  - `_run_planner_agent`：规划 JSON 大纲（每节含标题/意图/该引用的论文编号）。
  - `_run_writer_agent`：每个章节一个 Writer，**线程池并发**撰写，只注入本节相关文献（动态 RAG）。
  - `_run_mermaid_agent` + `_build_fallback_mermaid`：生成算法演进图，LLM 不给图时用「方法+年份」兜底。
  - `_check_grounding`：**张冠李戴检测**——专用 Agent 逐句核查「某方法是否真属于其引用的论文」。
  - `_validate_citations`：**引用越界检测**——正则扫所有 `[n]`，超范围的标记为幻觉。
  - `_validate_and_fix_mermaid`：**演进图时间校验**——以抽取年份为权威，纠正节点年份、调换「晚→早」箭头。
  - `_fallback_review`：无 LLM 时按规则拼一份降级综述。
- **`optimizer.py`** — 综述「审查—返工」优化。`Auditor`（找茬专家）对照源数据生成《缺陷报告》，
  `Reviser`（主编）据此定向重写；`Level 1` 仅润色、`Level 2` 一轮、`Level 3` 两轮；
  支持「接力棒缓存」——复用初稿已算好的幻觉扫描结果，省一次昂贵 LLM 调用。
- **`assistant.py`** — AI 选题助手。检索**前**的对话式 Agent，反问引导用户明确方向，
  在回复末尾用【】给出推荐检索词（前端渲染成「一键填入」按钮）。
- **`qa.py`** — 论文问答。检索**后**的 RAG 问答，只依据当前文献的标题/摘要/抽取结果/详评回答，
  强制 `[n]` 引用并校验越界；无 LLM 时退回关键词匹配。

#### LLM 封装 `src/llm/deepseek_client.py`

- 用 `requests` 直连 DeepSeek（OpenAI 兼容接口，不引入 openai SDK）。`chat()` 普通对话、
  `chat_json()` 强制 JSON。核心是 **`itertools.cycle` 密钥轮询**：每次请求 `next(key_cycle)`
  取下一个 Key，把并发压力均摊到多个账号，绕过单账号限流。

#### 前端 `templates/` + `static/`

- **`index.html`** — 单页界面：检索控制台、流水线日志、抽取评测面板、可视化网格（词云/趋势）、
  趋势分析卡、主题聚类、文献列表、论文问答、综述草稿+演进图、以及海报/详评/选题助手三个模态框。
- **`app.js`** — 前端全部逻辑：调 `/api/*`、渲染各图表（Chart.js）/词云/Mermaid/Markdown、
  把 `[n]` 渲染成角标（越界标红）、海报生成、各面板交互（评测、问答、选题助手、深度优化）。
- **`style.css`** — 样式。CDN 引入 Chart.js / wordcloud2 / marked / mermaid，无需 npm 构建。

#### 评测 `eval/`

- **`labeled.json`** — 12 条人工标注样本，每条含论文信息和 `gold` 标准答案（方法/数据集/指标/结论关键词）。
- **`compare.py`** — 规则法 vs LLM 抽取对比的 CLI 入口，复用 `evaluator.py`，打印 P/R/F1 和 ΔF1。
- **`topic_eval.py`** — 主题准确率评测，对应「论文主题准确率 ≥ 85%」要求（规则判定 / LLM 判定两种口径）。

#### 脚本与文档

- **`scripts/`** — `check_net.py`（诊断 arXiv/S2 连通性与代理）、`test_retrieval.py`（翻译+检索全链路）、
  `show_pipeline.py`（美化打印流水线 JSON）。仅调试用，不参与主流程。
- **`docs/DESIGN.md`** / **`README.md`** / **`期末报告.docx`** — 设计文档 / 使用指南 / 课程报告。

## 五、HTTP API 端点一览（`app.py`）

| 端点 | 作用 |
|---|---|
| `GET /` | 返回前端页面 |
| `GET /api/status` | 查询 LLM 是否可用 |
| `POST /api/pipeline` | **一键跑全流程**（检索→抽取→聚类→分析→综述） |
| `POST /api/retrieve` / `extract` / `cluster` / `review` | 分步调用（前端分阶段展示用） |
| `POST /api/deep_read_paper` | 单篇「精读」：抓全文 + LLM 深度抽取 |
| `POST /api/optimize_review` | 综述多级审查与返工优化 |
| `POST /api/chat_assistant` | AI 选题助手对话 |
| `POST /api/paper_qa` | 论文问答（RAG QA） |
| `POST /api/eval_compare` | 规则法 vs LLM 抽取评测（数据集/指标 P/R/F1） |

## 六、如何运行

```bash
# 1. 安装依赖（已配好的 conda 环境：nlp_agent_homework）
pip install -r requirements.txt

# 2. 配置密钥（可选，不配也能跑，功能自动降级）
cp .env.example .env        # 在 .env 填 DEEPSEEK_API_KEY=sk-xxx 或多个逗号分隔

# 3. 启动网页
python app.py               # 打开 http://127.0.0.1:5000

# 4. 命令行评测
python eval/compare.py            # 抽取对比（规则法，秒级）
python eval/compare.py --llm      # 含 LLM 抽取（需密钥）
python eval/topic_eval.py         # 主题准确率
```
