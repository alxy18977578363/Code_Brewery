## 第3页：项目背景与动机

- **痛点分析**：
  - 论文数量庞大（arXiv 每天新增上千篇），人工检索筛选极其耗时
  - 英文论文阅读门槛高，初学者难以抓住核心方法与结论
  - 归纳整理需要反复对比，工作量大且容易遗漏
- **现有方案的致命问题**：
  - 直接让大模型写综述 → 产生"幻觉"（编造不存在的论文、作者、实验结果）
  - 对严谨学术场景不可接受
- **我们的目标**：构建一个 **可信任、可追溯、可验证** 的自动文献综述系统

---

## 第4页：系统功能概览

- 用户输入研究主题 → 系统自动完成全流程：
  1. 🔍 双源论文检索（arXiv + Semantic Scholar）
  2. 📊 结构化信息抽取（方法/数据集/指标/结论）
  3. 🏷️ 主题聚类与趋势分析
  4. 📝 多智能体协作生成带引用的综述
  5. 🗺️ 自动绘制算法演进图（含时间校验）
  6. 🖼️ 一键生成学术海报与可视化展示
- **AI 选题助手**：对话式引导用户明确检索方向

## 第5页：相关技术概览

| 技术 | 说明 |
|------|------|
| RAG（检索增强生成） | 给大模型提供真实论文作为依据，避免幻觉 |

| 多智能体协作 | Planner / Writer / Grounding / Auditor / Reviser |

## 第8页：核心数据结构

- **Paper 数据类**（检索阶段）
  - paper_id、标题、摘要、作者、年份、期刊
  - 原文链接、代码链接、Star 数
- **StructuredRecord 数据类**（抽取阶段）
  - methods（方法）、datasets（数据集）、metrics（指标）
  - keywords（关键词）、conclusion（结论）
  - detailed_analysis（精读详评）、results（数据集-指标-数值三元组）
- 两种抽取路线（规则/大模型）输出格式完全一致，可直接对比

## 第9页：模块1 — 查询翻译

- **问题**：arXiv 99% 是英文论文，中文主题直接搜索效果差
- **方案**：
  - 非中文 → 原样返回
  - 含中文 → 调用 DeepSeek 翻译，强制保留所有关键概念和限定词
  - 大模型不可用 → 退回内置 NLP 术语对照表
- **踩坑**：早期提示词过度精简，"中文命名实体识别"被压缩为"named entity recognition"（丢失"中文"限定词）

---

## 第10页：模块2 — 检索与相关性重排

- **五步流程**：
  1. arXiv 检索（feedparser 解析 XML）
  2. Semantic Scholar 检索（按影响力排序，新论文不按引用排）
  3. 跨源去重（标题归一化比对）
  4. **IDF 相关性重排**（核心优化）
     - 通用词降权（network/learning），特异词升权（graph/chinese）
     - 标题命中加倍计分，低于阈值的离题论文被剔除
  5. 代码仓库 & Star 抓取（多源降级爬虫，按 Star 排序）

---

## 第11页：模块3 — 中文信息抽取（核心）

- **两条技术路线并行，输出一致，可直接对比**：

| | 规则方法 | 大模型方法 |
|---|---------|-----------|
| 技术栈 | jieba + 自建词典(174条) + 正则 | DeepSeek 结构化 JSON 抽取 |
| 速度 | 本地秒级，~1.9万篇/秒 | 依赖网络 |
| 优点 | 可解释、低成本、可评估 | 理解力强、对新术语鲁棒 |
| 体现 | 课程基础能力 | 大模型增强能力 |

- 抽取内容：方法、数据集、指标、关键词、结论句

## 第12页：模块4 — 主题聚类与趋势统计

- TF-IDF 向量化（最多 2000 特征词）
- KMeans 自动聚类，簇数自适应：
  - <4篇不聚类 / <8篇分2类 / <15篇分3类 / <30篇分4类 / ≥30篇分5类
- 每簇取高权重词 + 高频方法词作为主题标签
- 年份趋势统计，反映方向热度变化

## 第13页：模块5 — 多智能体综述写作（核心亮点）

- **拒绝**"一次让大模型写全文" → 质量崩塌 + 幻觉泛滥
- **采用 SOP 多智能体协作**：

```
Planner（规划大纲）
    ↓ 动态RAG上下文路由（按章节精准分配论文）
Writer Agents（并发撰写各章节）
    ↓
Grounding Agent（张冠李戴检测）
    ↓
Auditor（找茬挑错） ⟷ Reviser（定向返工）
```

- **两道幻觉防线**：
  - 引用越界检测（正则扫描 [n]，超范围标红）
  - 术语级张冠李戴检测（核查引用编号背后的论文是否真的支持该句话）

---

## 第14页：模块6 — 审查与返工优化

- **三档优化强度**：
  - Level 1：轻量润色，速度最快
  - Level 2：Grounding扫描 + Auditor生成缺陷报告 + Reviser定向重写
  - Level 3：两轮"挑错→返工"循环，进一步压低幻觉
- Auditor 与 Reviser 形成 **对抗博弈**
- 每轮中间过程实时日志回显，过程完全透明
- 优化完成后自动重算引用越界、混淆指标

---

## 第15页：模块7 — 算法演进图与时间校验

- **Mermaid Agent** 生成演进图代码
- 多级容错正则提取引擎（兼容多种写法）
- **时间正确性校验**（确定性保障）：
  - 解析图中节点与箭头
  - 用论文真实年份校正节点年份
  - 调换"晚→早"的倒置箭头
- 模型未给图时，用"方法+年份"确定性生成兜底

## 第16页：模块8 — 高并发引擎

- **多 API Key 轮询**：itertools.cycle 构建密钥池，Round-Robin 均匀分发
- **动态线程扩容**：并发上限 = min(20, 5 × 密钥数)
  - 1 Key → 5 线程 / 3 Key → 15 线程 / 上限 20
- 无需改代码，增减 Key 即可线性扩展吞吐
- **效果**：约1分钟内完成数十篇论文精读 + 上万字综述撰写
- 无 Key 时自动降级到本地规则方法

## 第19页：实验结果 — 信息抽取评测

- **自建词典规模**：174条术语（方法79 + 数据集56 + 指标39）
- **规则抽取 P/R/F1**：

| 字段 | Precision | Recall | F1 |
|------|----------|--------|------|
| 方法实体 | 0.9068 | 1.0000 | **0.9435** |
| 数据集实体 | 0.9408 | 1.0000 | **0.9623** |
| 评价指标 | 0.7800 | 0.7700 | **0.7367** |

- **吞吐性能**：50–400条样本，稳定 ~1.9万篇/秒

## 第20页：实验结果 — 综述质量与幻觉控制

- **三项作业要求 → 可检查的程序指标**：
  1. ✅ 主题准确率 ≥ 85%：IDF重排过滤离题论文
  2. ✅ 综述无明显幻觉：引用越界检测 + 张冠李戴检测 + 审稿返工闭环
  3. ✅ 演进图无时间错误：Mermaid时间校验自动修正
- 多智能体 SOP vs 单模型一次生成：
  - 每个Writer只接收本章节论文 → 降低串扰
  - 引用编号自动扫描 → 不依赖人工检查
  - Grounding/Auditor/Reviser 闭环 → 发现→定位→修复

## 第22页：不足与改进方向

1. **词典覆盖度**：从NLP扩展到医学、法律等领域需继续扩展术语词典
2. **API限流**：Semantic Scholar 免费接口有限，需配置Key或本地缓存
3. **聚类方法**：当前 TF-IDF+KMeans 轻量但语义表达弱，可替换为 text2vec/sentence-transformers
4. **智能体升级**：从固定流水线 → LLM自主决策（是否扩大检索、启用全文精读等）

## 第23页：心得体会

- 真正有价值的AI应用 ≠ 把所有问题都交给大模型
- **大模型放在合适的位置** + 传统NLP方法 + 工程规则 + 可视化手段 = 可靠系统
- 规则方法：速度快、可解释、可评估 → 系统稳定运行的底座
- 大模型：强大但必须配合检索、引用校验和审查机制
- 项目不是简单堆叠工具，而是围绕"如何自动生成可信文献综述"组织各技术点
