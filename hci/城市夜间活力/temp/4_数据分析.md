# 数据分析

## 指标体系设计
- 基础类：POI 数量、商户密度、平均评分、评论量
- 流量类：夜间客流（出租车上下车、OD 矩阵）、客流峰值时段
- 活力类：夜间活力指数（聚合：商户密度、客流、评论活跃度、营业时段覆盖）
- 结构类：业态占比（餐饮、娱乐、零售、住宿等）、商圈内多样性指标

## 特征工程与建模
- 特征构造：按 `grid_id` 汇总历史小时特征（近 7/30 天的均值、方差、环比、同比）
- 权重设定：使用可配置权重组合生成 `night_vitality_index`，并提供可视化的权重调节界面
- 简单模型：可使用线性回归/岭回归解释指标与外部因子（天气、节假日、临时事件）之间的关系
- 聚类分析：对街区或栅格做 KMeans 聚类，识别“高活力-高多样性”“高流量-低业态多样性”等类型

## 统计验证与显著性测试
- 相关性分析：Pearson/Spearman 检验指标之间的相关性（如评分 vs 活力）
- 显著性检验：使用 t 检验或非参数检验比较不同区域或时段的差异
- 稳定性检查：对合成数据与真实数据进行交叉验证，评估指标随采样策略变化的鲁棒性

## 分析产出样例（自动化脚本）
- 日常报告：生成每日/每周活力排行榜（前 N 街区）与增长榜
- 异常检测：基于历史分布检测突发流量或评分异常并生成告警
- 洞察笔记：对显著变化的区域生成自动化的“可能原因”候选（例如：节假日活动、交通管制、恶劣天气）

## 可重复的分析流程
- 使用 Jupyter/脚本化分析步骤，将关键图表与表格输出到 `reports/` 目录
- 指标计算代码应作为可重用模块（例如 `scripts/compute_metrics.py`）并通过单元测试覆盖关键函数

  hour,
  0.4 * normalized_poi_count
  + 0.3 * normalized_taxi_flow
  + 0.2 * normalized_review_count
  + 0.1 * normalized_business_hours AS night_vitality_score
FROM (
  -- 子查询负责按指标归一化
) t;
