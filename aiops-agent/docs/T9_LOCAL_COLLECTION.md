# T9：本机指标和指定日志采集

## 使用方式

启动项目后打开 `http://127.0.0.1:8000/`，在“实时分析”区域点击“采集本机数据”。系统会采集一次数据、完成 T4/T5 分析并直接显示结果，不需要使用 Swagger 或手动填写 JSON。

也可以在终端单独查看本次采集内容：

```powershell
python src/collect_local.py
```

## 允许采集的数据

| 数据 | 来源 | 说明 |
|---|---|---|
| CPU 使用率 | 当前电脑 | 通过 `psutil` 采集一次 CPU 百分比。 |
| 内存使用率 | 当前电脑 | 通过 `psutil` 读取系统内存百分比。 |
| 磁盘使用率 | 项目所在磁盘 | 只读取项目所在盘符的容量百分比。 |
| 系统负载 | 当前电脑 | Windows 不支持时为 `null`。 |
| WARN/ERROR 日志 | `runtime/local_events.log` | 只读取这个明确指定的项目内文件，最多读取末尾 128 KB、50 条事件。 |

以下业务指标没有真实应用监控来源，因此当前固定为 `null`：请求速率、响应时间、错误率、数据库连接使用率。它们不会被伪造，也不会单独导致异常判断。

## 日志边界

采集器不会扫描桌面、文档、浏览器记录、系统事件日志或任何任意用户路径。它只读取项目目录内的 `runtime/local_events.log`；该文件不存在、不可读取或没有 WARN/ERROR 行时，分析仍会继续，并在页面中显示日志状态。

日志文件中的包含 `WARN` 或 `ERROR` 的行会被转换为 T3 日志输入。例如项目自己的服务或演示程序可以向该文件写入：

```text
2026-08-30T10:20:00+08:00 ERROR database connection timeout
```

这类日志会作为分析证据，不会触发任何自动修复。

## API

- `GET /api/local-observation`：预览一次允许采集的本机观测数据。
- `POST /api/collect-now`：采集、保存并分析一次本机数据。请求体只需 `{"use_model": false}`。

两者都只监听本机 `127.0.0.1`。
